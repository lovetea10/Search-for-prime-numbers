Данный репозиторий был создан с целью эффективного нахождения простых чисел в больших диапазонах с помощью параллельных вычислений.

## Структура проекта

```
prime_mpi2/
├── CMakeLists.txt
├── src/
│   ├── main.cpp        # Точка входа, логика MPI-распределения
│   └── sieve.cpp       # Реализация решета Эратосфена (обычного и сегментного)
├── include/
│   └── sieve.h         # Заголовочный файл
└── build/
    └── prime_mpi       # Скомпилированный бинарник
```

## Как это работает

Программа делит диапазон `[2, N]` между всеми MPI-процессами. Каждый процесс независимо просеивает свой сегмент с помощью решета Эратосфена, после чего мастер-процесс собирает результаты и выводит общее количество найденных простых чисел и время выполнения.

## Сборка

```bash
cd prime_mpi2
mkdir build
cd build
cmake ..
make
```

---

## Запуск

**На двух машинах (master + n01):**
```bash
mpirun --prefix /home/user/apps -np 4 -H 192.168.26.1:2,192.168.26.111:2 ./prime_mpi 100000000
```

**Замечания:**
- Бинарник `prime_mpi` должен находиться по одинаковому пути на обеих машинах
- Между машинами должен быть настроен SSH без пароля

## Сравнение производительности

### Тест: N = 10 000 Найдено: 1229 простых чисел.

| Процессы | Время выполнения | Ускорение |
|:--------:|:----------------:|:---------:|
| 1        | 5.70e-05 сек     | 1.0       |
| 2        | 5.88e-05 сек     | 0.97      |
| 4 (2 ВМ) | 3.53e-05 сек     | 1.61      |

> Для N=10 000 диапазон 10 000 — маленький. Само вычисление занимает микросекунды (слишком быстро считается), а MPI добавляет накладные расходы: синхронизация, передача данных между процессами (а это больше по времени происходит, чем сэкономленное время).

### Тест: N = 1 000 000 000 Найдено: 50847534 простых чисел.

| Процессы | Время выполнения | Ускорение |
|:--------:|:----------------:|:---------:|
| 1        | 9.99 сек         | 1.0       |
| 2        | 5.39 сек         | 1.85      |
| 4 (2 ВМ) | 6.19 сек         | 1.61      |

> Для N=1 000 000 000 процессы на разных машинах, MPI должен передавать данные через сетевой интерфейс. В нашем случае это виртуальная сеть между ВМ, которая намного медленнее общей памяти внутри одной машины.
2 процесса на 1 машине — общение через RAM (почти мгновенно это происходит), 4 процесса на 2 машинах — 2 процесса на n01 считают, потом результат идёт через сеть на master и съедает выигрыш от дополнительных ядер.
